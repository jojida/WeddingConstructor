## 4. Регистрация и почта (главная эпопея)

**Симптом:** не приходит письмо с кодом при регистрации.

**Что нашли и починили:**
1. Бэкенд слал `secure:true` всегда → на порту 587 письмо падало по SSL. Починено (`secure = порт===465`).
2. Сбой почты ронял вход 500-й → сделал best-effort, ответ не ждёт письма.
3. **Корень проблемы:** хостер (VPS) **блокирует исходящие SMTP-порты 465 и 587** (проверено — оба `BLOCKED`). Значит SMTP с сервера не работает в принципе.
4. **Решение:** отправка через **HTTP API (порт 443)**. Модуль `backend/src/lib/email.ts` умеет **Resend и Brevo** (приоритет: `RESEND_API_KEY` → `BREVO_API_KEY` → SMTP). `auth.ts` и `notify.ts` переведены на него.
5. Выбран **Brevo**. Ключ провалидирован, подтверждённый отправитель — `vadimegiazaroff@gmail.com`. Тестовая отправка через Brevo прошла успешно (лог: `✉️ письмо отправлено`).

**Нужные переменные в `backend/.env`:**
```
BREVO_API_KEY=xkeysib-…
MAIL_FROM=vadimegiazaroff@gmail.com
MAIL_FROM_NAME=WeddingCraft
```

**Коммиты:** `0ee0071`, `4c40550`, `d2b3358`.

## 5. Ошибка на странице регистрации (реальная причина «Ошибки»)

**Нашли по скриншоту:** страница `/auth` была **парольной** и дёргала `/api/auth/login` и `/api/auth/register`, **которых в бэкенде нет** (вход беспарольный, по коду) → любой сабмит = «Ошибка». Плюс на сервере крутился **старый фронтенд** (бренд ещё «Eloquence»), т.к. пересобирали только `wedding-api`.

**Сделано:** переписал `/auth` под вход/регистрацию **по коду на email** (`send-code`/`verify-code`), как в модалке. Аккаунт создаётся автоматически. Проверено локально: поле email, кнопка «Получить код», без пароля, бренд WeddingCraft.

**Коммит:** `b23477c`.

## 6. Сайт пользователя на корневом адресе

**Задача:** зарегистрированный пользователь получает свой сайт вида `weddingcraft.ru/mysite` (оплату пока не вводим).

**Сделано:**
- Убрал гейт «не оплачено» в `by-slug`/`by-domain` — сайт доступен сразу.
- Slug стабилен (не перегенерируется при смене имён).
- Новый `PATCH /api/invites/:id/slug` — задать свой адрес (валидация + резервные слова + уникальность).
- Корневой маршрут `app/[slug]/page.tsx` → отдаёт приглашение (`weddingcraft.ru/<slug>`). Статические маршруты в приоритете.
- В Кабинете — карточка **«Адрес сайта»**: ссылка, копирование, открытие, смена slug.

Проверено локально: смена slug на «mysite», доступ без оплаты, `/mysite` → 200, зарезервированные/короткие отклоняются, статические страницы целы.

**Коммит:** `e1007d8`.

## ⚠️ Что осталось сделать (на стороне владельца)

### A. Пересобрать ФРОНТЕНД (ключевой недостающий шаг)
Всё это время ребилдился только бэкенд, поэтому на сайте оставалась старая версия. Полный деплой:
```bash
cd /var/www/wedding
git pull
cd backend && npm run build && pm2 restart wedding-api
cd ../frontend && npm run build && pm2 restart wedding-frontend
```
Потом открыть сайт с **Ctrl+Shift+R** (сброс кэша). После этого: бренд WeddingCraft, вход по коду, светлый фон превью, карточка «Адрес сайта».

### B. Проверить регистрацию
Сайт → «Войти/Регистрация» → email → «Получить код» → код с почты (через Brevo) → Кабинет.
Диагностика на сервере: `pm2 logs wedding-api --lines 15` (ищем `✉️ письмо отправлено`).

### C. Доставляемость писем
Отправитель сейчас `@gmail.com` через Brevo → mail.ru может класть в «Спам». Для надёжности — **аутентифицировать домен `weddingcraft.ru` в Brevo** (SPF/DKIM записи на reg.ru) и поменять `MAIL_FROM` на `support@weddingcraft.ru`.
> Открытый вопрос: дошли ли тестовые письма (коды 123456/994850) на mail.ru и куда — входящие или спам.

### D. Безопасность
API-ключ Brevo светился в переписке — после проверки лучше пересоздать его в Brevo и обновить в `.env`.
