## 1. Глубокий анализ ниши электронных приглашений

**Запрос:** честно оценить рынок (РФ и мир), сколько можно заработать, как гнать органику, сравнить сайт с конкурентами.

**Вывод (кратко):**
- **Рынок РФ** — ~100–250 млн ₽/год. Браков ~880 тыс./год (2024, снижается), платят за сайт-приглашение 5–10% пар с банкетом → ~30–60 тыс. заказов/год на всех. Средний чек 2–4 тыс. ₽. Сезонность: пик февраль–июнь.
- **Потолок для соло-фаундера:** 50–200 тыс. ₽/мес чистыми через 6–12 мес; лидеры (WedWed 4980₽, WeddingPost от 2990₽) — единицы млн ₽/мес.
- **Мир** — глобальный рынок ПО $1.2–1.8 млрд, но там свадебные сайты бесплатны (Zola ~$120M на реестрах подарков; Paperless Post всего ~$18M). Платный e-invite на Запад бессмысленен. **Вектор экспансии — СНГ** (Казахстан, Узбекистан, Армения: большие свадьбы, русский язык, слабая конкуренция).
- **Экономика рекламы:** CPC в Директе 30–100₽, CAC 1500–5000₽ → при чеке ~2000₽ прямая реклама убыточна. Выигрывают органика + виральность + высокий чек с апселлами.
- **Органика:** виральная петля №1 (футер «сделано на WeddingCraft», каждое приглашение видят 50–150 гостей), SEO под Яндекс, контент-магниты («текст приглашения на свадьбу»), Pinterest, Reels/VK-клипы, партнёрки с организаторами/ведущими (комиссия 20–30%).
- **Потенциал сайта:** продукт ~80% готов, маркетинг ~5%. Конкурентные преимущества уже есть (кабинет гостей, персональные ссылки — как у дорогих тарифов конкурентов). Главные пробелы были: оплата выключена, SEO-ноль, нет соцдоказательств, стоковые фото в hero, мало шаблонов.

## 7. Свой домен — самообслуживание (`d8b89f3`, `24a28d0`)

- Новый роутер `backend/src/routes/domains.ts`:
  - `GET /api/domains/check?domain=` — ask-валидатор для Caddy on-demand TLS (200 только оплаченным). **В реальности сервер на nginx, не Caddy — endpoint не используется, лежит без вреда.**
  - `GET /api/domains/status/:inviteId` — DNS-проверка (`dns.resolve4` vs `SERVER_IP`, дефолт 89.191.226.237).
- `invites.ts`: PATCH домена защищён на бэке — только Премиум (403), валидация формата (400), запрет weddingcraft.ru, дубль → 409, пустая строка = отвязать.
- Кабинет, вкладка «Домен»: инструкция с двумя A-записями на IP + кнопка «Проверить подключение» (✓/✗ по каждой записи).
- **CORS (`24a28d0`):** сайт-приглашение на своём домене шлёт RSVP/guest на `api.weddingcraft.ru` cross-origin. Бэкенд раньше отклонял неизвестный Origin → анкета на клиентском домене не работала. Теперь Origin разрешается, если его хост (без www) привязан к приглашению (`customDomain`). Проверено curl'ом: привязанный + www разрешены, чужой запрещён.
- **Резолв:** Next 16 middleware = `proxy` → `frontend/src/proxy.ts` ребейзит чужой Host на `/by-domain/<host>`.

## 10. Деплой — сага (важные открытия)

**DEPLOY.md был неточен.** Реальность сервера (89.191.226.237, Ubuntu):
- **Edge — nginx + certbot** (Let's Encrypt), НЕ Caddy. `caddy.service` замаскирован и мёртв.
- На сервере **два проекта**: `weddingcraft.ru` и VPN-сервис `vegipn.net` (процесс `vpn-frontend` в pm2). Переключать edge на Caddy нельзя — задело бы оба.
- **Порты:** nginx проксирует `weddingcraft.ru` → **`localhost:3002`** (не 3000!), `api.weddingcraft.ru` → `:4000`. pm2-процессы: `wedding-api` (id 7), `wedding-frontend`, плюс дубль `backend` (id 6).

**Грабли деплоя, которые всплыли:**
1. `git pull` спотыкается о локально изменённый `frontend/package-lock.json` → перед pull делать `git checkout -- frontend/package-lock.json`.
2. Прод отдаёт старую сборку → перед `npm run build` фронта делать `rm -rf .next`.
3. Новые пакеты (`@fontsource/*`) не были на сервере → `npm install` при изменении package.json. Именно это ломало сборку и шрифт арки.
4. `NODE_ENV` не выставлен на сервере → анти-фрод-гейт оплаты не срабатывает (риск бесплатной публикации).
5. Опечатка в env: код читает `YUMONEY_*`, в DEPLOY.md было `YOOMONEY_*`.

**Свои домены на nginx (не Caddy):** on-demand TLS в nginx нет — под каждый клиентский домен выпускается сертификат certbot + добавляется server-блок (proxy на :3002, заголовки 1-в-1 с боевым блоком weddingcraft.ru). Скрипт проверен (падает только на несуществующем/не-ASCII домене — ожидаемо). Кириллические домены (.рф) → перевести в Punycode (`python3 -c "print('денис.рф'.encode('idna').decode())"`).
